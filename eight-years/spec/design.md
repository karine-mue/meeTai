# 設計書（実装前）

作成: 実装着手前。以降の実装はこの文書を基準とし、変更した場合は `LOG.md` に記録する。

---

## 1. 対象

女子高校生の高校二年（2015年度）から8年間、2015-04-01 〜 2023-03-31 の記録。

本人は画面上「あお」とだけ表示される。氏名・学校名・勤務先・地名は一切出さない。
年齢・学年・進路・職種も画面上では明示しない（後述の「周辺の変化」でのみ推測可能にする）。

## 2. 媒体

架空の記録アプリ **ヌイシロ**。
半公開の短文＋写真の記録アプリで、本人のプロフィール画面（自分の投稿一覧）とダイレクトメッセージ画面を持つ。

成果物の各画面は「本人の端末に残っていたスクリーンショット」という体裁を取る。
したがって各画面は次の二層を同時に持つ。

- **記録層**: 投稿の日時・本文・写真
- **端末層**: スクリーンショットを撮った時刻、電池、通信、ファイル連番

### 2.1 表示順

アプリは投稿一覧に「新しい順 / 古い順」の並び替えを持ち、本人は常に「古い順」を選んでいる。
画面内の投稿は上から下へ時系列昇順。これはUI上のトグルとして画面に表示されるので、説明を要しない。

### 2.2 仕様変更（8年間で1回）

`v1` → `v2` の変更を **2018-09-29 と 2019-12-03 の間** に1回だけ置く。理由は画面上で説明しない。

| | v1（2015-05 〜 2018-09） | v2（2019-12 〜 2023-03） |
|---|---|---|
| 配色 | 明色 | 暗色 |
| カード | 角なし・罫線区切り | 角丸カード |
| アカウント表記 | `ID 4417-08` | `@8261-30` |
| 日時表記 | `2015/05/07 (木) 07:48` | `2019.12.03 火 · 07:11` |
| リアクション | `☆` | `◇` |
| 並び替えUI | テキストリンク | セグメントコントロール |
| タブ | 4つ | 3つ |

アカウントIDも同時に変わる（移行）。端末は変えないので、ファイル連番は変更をまたいで連続する。

## 3. 縦糸

**落ちている片方だけの軍手を見つけて撮る**。

- 年に1回程度、本人が偶然見つけたときにだけ投稿する。
- 季節に紐づかない（軍手は通年で落ちている）。集団的な年中行事ではない。
- 本人の私的な習慣であり、画面上でその意味は一度も説明されない。

## 4. 事件を作らない

大きな出来事は書かない。8年分の投稿はすべて、その年齢・その生活で最も頻度の高い事象で埋める
（電車、弁当、洗濯機、自販機、コンビニ、録画、製氷、段ボール等）。

卒業・進学・就職・引っ越しは**それ自体を一度も書かない**。次の指標の変化としてのみ現れる。

| 時期 | 画面に現れる変化 | 書かないこと |
|---|---|---|
| 〜2016 | 平日昼の投稿がある（`context: school`）、夜は自宅Wi-Fi | 学校 |
| 2017 | 平日昼が消える。始発の時間帯が出る。自宅でも通信が `mobile` になる | 卒業・進学 |
| 2018 | 昼の投稿が `context: work` として戻る。夜が固まる | 就職 |
| 2020 | 平日昼が自宅に戻る。Wi-Fi・充電中・電池100% | 在宅の理由 |
| 2021 | 乗り換えが増える。段ボールが残っている。通信が `mobile` 中心に戻る | 引っ越し |

## 5. 数値層

各画面（`kind: feed` / `dm`）が持つ値。

### 5.1 記録層
- 投稿日時（分まで）、曜日（実カレンダー）
- 画面内は昇順、画面間は非重複で昇順

### 5.2 端末層
- `shot_at`: スクリーンショット日時。画面内の全記録より必ず後
- ステータスバーの時刻は `shot_at` の HH:MM をそのまま表示（レンダラが導出）
- `battery` 1..100、`charging` 真偽、`network` ∈ {wifi, mobile, weak, none}、`bars` 0..4
- `seq`: 端末内のファイル連番。撮影順に単調増加（`IMG_0412` 形式）
- `context` ∈ {home, school, work, out, transit}: その時刻に本人がどこにいるか

### 5.3 端末状態と行動の整合ルール（実装が守る規約）

| ID | 規則 |
|---|---|
| R1 | `charging` ⇒ `context ∈ {home, work}` |
| R2 | `context ∈ {out, transit}` ⇒ `charging == false` |
| R3 | `00:00 ≤ 時刻 ≤ 05:59` ⇒ `context == home` |
| R4 | `context == school` ⇒ `08:00 ≤ 時刻 ≤ 18:00` かつ 月〜土 |
| R5 | `context == out` かつ 19時以降 ⇒ `battery ≤ 55` |
| R6 | `charging == false` かつ 08:59以前 ⇒ `battery ≥ 60`（夜間充電明け） |
| R7 | `network == wifi` ⇒ `context ∈ {home, work}` |
| R8 | `context == transit` ⇒ `network ∈ {mobile, weak, none}` |
| R9 | `network == none` ⇒ `bars == 0` / `weak` ⇒ `bars ≤ 1` / `mobile` ⇒ `bars ≥ 2` / `wifi` ⇒ `bars ≥ 1` |
| R10 | `battery == 100` ⇒ `charging == true` |
| R11 | `charging` かつ `context == home` かつ 00〜06時 ⇒ `battery ≥ 70` |
| R12 | スクショ時刻が画面内最新投稿の90分以内かつ同日なら、両者の `context` は一致する |

投稿にも `context` を持たせる。投稿は電池・通信を持たないので、投稿に適用するのは R3・R4 のみ。
R1・R2・R5〜R12 はスクリーンショット（`device`）にのみ適用する。

## 7. 実装

```
src/record.json     単一の真実（全画面・全数値）
src/life.py         読み込みと年度・曜日ユーティリティ
src/validate.py     検証関数群（テストから呼ぶ純粋関数）
src/assets/*.css    base / v1 / v2
src/render.py       record.json → src/build/*.html
src/shoot.py        Playwright で src/build/*.html → output/*.png、寸法と溢れを manifest.json に記録
```

- 画面サイズ 390×844 CSS px、`deviceScaleFactor: 2` → 780×1688 px の PNG
- 画像生成APIは使わない。写真領域は単色・グラデーション・図形のみ
- フォントは IPAGothic（環境に存在）

検証の設計は `spec/verification.md` に分けて書く。
